# Limitations

Stated up front and surfaced in-product where they apply (run limitations, INCONCLUSIVE verdicts, "coming soon" flags). Regenerated by `npm run benchmark -- --render`.

## By design in the shipped product

- **CAPTCHAs are not solved** — A CAPTCHA ends the case as BLOCKED with the lanes (test keys, allowlist, human hand-off). Nothing in the codebase solves or evades challenges. _Packs: form-app, auth-blocked._
- **Bot protection is not evaded** — Cloudflare / Akamai / PerimeterX / DataDome / Imperva are classified and reported with remedies; no fingerprint spoofing, proxy rotation or replayed attestation exists. _Packs: auth-blocked._
- **Cloud egress addresses change** — Railway egress IPs can change on redeploy; allowlists must be re-checked (preflight_access) before a campaign. _Packs: auth-blocked._
- **Visual judgement depends on the model** — Layout and colour defects are judged from screenshots by the step model; subtle rendering issues below a few pixels are not reliably caught. _Packs: form-app, e-commerce, data-dashboard, exploratory-hunt._
- **Race conditions are probabilistic** — Oversell and double-submit probes fire a small number of near-simultaneous requests; a race that needs sub-millisecond timing may not reproduce on a given run. _Packs: e-commerce, exploratory-hunt._
- **Exploration is bounded by design** — The action cap and path rules stop an exploration; coverage is reported against the map, not against an unknown whole. _Packs: exploratory-hunt._
- **Performance numbers include the browser pool** — Web vitals are measured inside Browserless; absolute values carry the pool's network position — compare against a baseline from the same pool. _Packs: performance._
- **Screen readers are not driven** — Accessibility findings come from the tree and computed properties; VoiceOver / TalkBack behaviour is predicted, and a manual pass is requested. _Packs: accessibility._
- **Firefox / WebKit need a local engine** — Non-Chromium engines run only where a worker or API host has them installed (LOCAL_BROWSERS=1); a missing engine fails its cell truthfully. _Packs: locale-matrix, cross-surface._
- **Estimates need history** — Campaign prices come from the project's own run history; a new project gets a wide confidence range until a few runs exist. _Packs: volume._
- **No pinch on Appetize** — The Appetize automation API has tap and single-finger swipe only; pinch cases are INCONCLUSIVE with alternatives (real-device lane). _Packs: mobile-fixture, cross-surface._
- **iOS simulators: no network / battery / push scripting** — Offline, battery, font scale and notifications are INCONCLUSIVE on iOS in Appetize and covered on Android. _Packs: mobile-fixture._
- **Unsigned macOS builds re-ask permissions** — TCC grants are keyed to the code signature; until a Developer ID signs the app, Accessibility / Screen Recording must be re-granted after updates. _Packs: canvas-fixture._

## Needs a customer entitlement or credential

- **Adobe connectors need enterprise entitlements** — Firefly / Analytics / CJA / AEM MCP servers are wired as presets and tested against mocks; live use needs an IMS token with the right entitlements.

## Roadmap — stated, not shipped

- **Upgrade-over-existing needs a real-device lane** — Appetize pins a session to one build; upgrade paths are tested as two runs with backend verification, or on a real-device connector. _Packs: mobile-fixture._
- **Desktop tests need a paired machine** — Cloud desktop VMs (cua Fleets / Lume) are coming soon; today a Mac / PC / Linux box runs the KaDeep worker. _Packs: canvas-fixture._
- **Windows worker not validated in this pass** — The Windows worker builds through the workflow; end-to-end validation on a Windows machine is pending. _Packs: canvas-fixture._
- **Real devices are a connector tier** — The DeviceProvider interface is shipped; BrowserStack / Sauce / USB-farm lanes plug in but are not bundled.
